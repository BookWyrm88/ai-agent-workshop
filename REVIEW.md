## Try the changes

1. Select an agent, choose **Lounge** in the room or floor controls, then **Move [name] here**. The operator leaves its desk, walks along a saved route and occupies a reserved lounge seat.
2. From the lounge, send **Summarize the sample document**. The task stays queued until the operator returns to its own workstation. Open Laboratory's shared timeline to inspect movement and execution events.
3. Set **After completing work → Return to lounge**, then run another task. It returns only when its work queue is clear. A full lounge leaves it at its desk with an explanation.
4. Inspect Library, Briefing, Task operations and Memory archive. Move an idle operator there, inspect occupancy, or open that location's real application controls. These actions are explicit; an agent does not autonomously read library material or reason during travel.

Save changes and refresh: identity and historical task snapshots stay intact. New agents use the same human editor in Neon; Spectrum and Forest retain their companion editor.
6. In **Task queue**, enable **Require my approval for new assignments**. Assign a new task, review its saved instructions, and approve or reject it. Refresh while approval is pending: it remains waiting and the queue is held. Approving a held task still requires **Resume queue**.
7. Create a safe demo pair and run **Research → Evaluation**. The payload contains the actual research output. Select the route or message chip for the inspector. Both histories and Laboratory record the same message. An evaluator away from its desk returns before processing it.
8. Try the systems-board nodes in Blueprint, diagnostics counts in Laboratory, cross-agent dispatch columns, operator directory and context vault. Each count comes from saved records. Nodes open or focus working controls.
9. Rest and restore an idle agent in the roster. Its room occupancy is released; its identity, versions and history remain. Switch themes in Settings; locations and appearance configuration remain saved. Spectrum and Forest show off-desk agents in a compact zone schematic, not the Neon walking scene.

## Review limits and deferred work

- Automated tests run real application code in jsdom, which does not render a browser layout. Browser automation rejects the local-file preview under its URL policy. No successful rendered screenshot, desktop/mobile layout audit, screen-reader certification or full visual accessibility audit is claimed.
- Please inspect walking alignment, seated poses, overlapping labels, keyboard traversal and narrow-screen scrolling in your normal browser. Reduced motion shows the reserved destination without travel animation; the recorded arrival still occurs when the simulator transition finishes.
- Routes use fixed walking lanes and reserved destination seats. They prevent two operators sharing a destination seat but are not full obstacle-aware or crowd pathfinding. Operators may cross during transit. Neon has animated movement; the other themes show current zones and destination text.
- Characters are lightweight layered SVG operators with simple posture, limb and typing animation. Fully illustrated, individually rigged human characters and more elaborate seated/walking poses remain polish work. The earlier generated sprite asset is retained.
- Blueprint is an interactive projection of the fixed simulation path, not an editable orchestration graph. The other terminals improve access to existing features; they are not new backend systems.
- No real models, external tools, autonomous reasoning, semantic memory retrieval, measured tokens, background execution or remote sync are provided. Approval gates apply to this local simulator, not external actions.
- Spatial history retains the latest 500 events. Task histories remain separate. Refresh restores an interrupted move at its reserved destination and records that recovery; it does not claim movement or tasks occurred while closed.

The prepared Pages file remains **docs/index.html**. Publish or merge only after explicit user approval. Never move the preserved `v0.1.0-rainbow` tag.
